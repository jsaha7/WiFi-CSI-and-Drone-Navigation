# WiFi-CSI-and-Drone-Navigation
Thesis on whether WiFi Channel State Information (CSI) is a usable signal for indoor drone localization when cameras/IMU struggle (dusty warehouses, low light, feature-poor corridors).
# Part 1 — Read and think

The pitch behind CSI-based localization is that off-the-shelf WiFi NICs expose per-subcarrier, per-antenna amplitude and phase for every received packet, instead of a single RSSI scalar. A 20 MHz 802.11n link with 3 antennas gives you 30 subcarriers x 3 antennas = 90 complex numbers per packet, and that vector changes in a structured way depending on where you are and what the multipath environment looks like. That's a lot more to work with than one RSSI number per link.

DeepFi (Wang, Gao, Mao & Pandey) is the most literal version of "throw the raw CSI amplitudes at a model." They train one autoencoder per reference point on the 90-value amplitude vector and localize a new sample by checking which RP's autoencoder reconstructs it best. It's basically nearest-neighbor fingerprinting with a fancier similarity function. It works fine in a static, unchanged room, but it inherits the core weakness of every fingerprinting approach: the "map" is only valid for the exact environment (furniture, walls, people) it was built in, and the training cost scales with the number of reference points because each one needs its own model.

SpotFi (Kotaru, Joshi, Bharadia & Katti) tries to do something more physically grounded: instead of memorizing what CSI "looks like" at a location, it estimates the angle-of-arrival (AoA) and time-of-flight (ToF) of each multipath component from the CSI phase, using a MUSIC-style super-resolution algorithm across the 3 antennas and 30 subcarriers. Then it picks out which path is plausibly the direct line-of-sight path and triangulates from there. This gets much better numbers (~40 cm median in their setup) and it generalizes without retraining for every point, but it needs calibrated phase across antennas, which in practice means solving for things like sampling time offset (STO) between antennas on the same NIC — this is finicky and part of why most "CSI localization" demos you find online quietly fall back to amplitude-only features, which throw away exactly the phase information SpotFi depends on.

The Ma, Zhou & Wang survey ("WiFi Sensing with Channel State Information") is useful mostly as a map of the field rather than a single technique: it buckets CSI sensing work into detection / recognition / estimation, and it's blunt that almost everything in the recognition/estimation buckets (localization included) is sensitive to environment change — a model trained in one room degrades in a new one because the multipath structure is a function of the specific furniture and walls, not just the person's location. That single point — CSI fingerprints are captured, not just measured, i.e. they encode a very specific static scene — is the thing that matters most for what follows.

Where this breaks down for a moving drone: everything above (DeepFi, SpotFi, and most of what the survey covers) assumes a static sensing platform: fixed antenna orientation, no self-motion, and a scene whose only source of CSI change is the target being localized. A drone violates literally every one of those assumptions simultaneously, which is really the crux of Part 2 below.

Sources: Wang, Gao, Mao, Pandey, "DeepFi: Deep Learning for Indoor Fingerprinting Using Channel State Information," IEEE WCNC 2015; Kotaru, Joshi, Bharadia, Katti, "SpotFi: Decimeter Level Localization Using WiFi," ACM SIGCOMM 2015; Ma, Zhou, Wang, "WiFi Sensing with Channel State Information: A Survey," ACM Computing Surveys 52(3), 2019.
